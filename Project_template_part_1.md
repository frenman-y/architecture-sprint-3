# Задание 1. Анализ и планирование

Чтобы составить документ с описанием текущей архитектуры приложения, можно часть информации взять из описания компании условия задания. Это нормально.

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут могут удалённо включать/выключать отопление в своих домах
- Система поддерживает включение/отключение отопления в доме
- Система поддерживает удаленное внешнее подключение к ней для управления

**Мониторинг температуры:**

- Пользователи могут просматривать текущую температуру в своих домах через веб-интерфейс
- Система поддерживает получение данных о температуре с датчиков, установленных в домах

### 2. Анализ архитектуры монолитного приложения

- Язык программирования: Java
- База данных: PostgreSQL
- Архитектура: Монолитная, все компоненты системы (обработка запросов, бизнес-логика, работа с данными) находятся в рамках одного приложения.
- Взаимодействие: Синхронное, запросы обрабатываются последовательно.
- Масштабируемость: Ограничена, так как монолит сложно масштабировать по частям.
- Развёртывание: Требует остановки всего приложения.

### 3. Определение доменов и границы контекстов

- Домен: управление устройствами
    - Поддомен: включение, отключение, настройка, регулировка устройств
    - Поддомен: конфигурации устройств
    - Поддомен: управление состоянием устройств
      - Контекст: хранение и определение текущего состояния устройств
    - Поддомен: удаленное внешнее подключение для управления
      - Контекст: api-сервис для удаленного подключения
- Домен: управление телеметрией
  - Поддомен: обеспечение передачи данных между устройствами и сервером
- Домен: мониторинг температуры
  - Поддомен: получение данных о температуре с датчиков
    - Контекст: запрос к датчикам от сервера
    - Контекст: отображение температуры в веб-интерфейсе
- Домен: наблюдение за домом
  - Поддомен: стриминг видео с устройств камер
- Домен: управление пользователями
  - Поддомен: регистрация и авторизация
  - Поддомен: настройки и предпочтения для пользователей
- Домен: пользовательский веб-интерфейс
  - Поддомен: взаимодействие с устройствами
  - Поддомен: просмотр информации об устройствах, статистики

### **4. Проблемы монолитного решения**

- Проблемы со скоростью связи. Синхронные взаимодействия с датчиками могут вызывать значительные задержки
- Масштабируемость ограничена, так как монолит сложно масштабировать по частям. 
- Надежность. Ошибка в одном модуле может повлиять на доступность всего приложения.
- Недостаточная гибкость. Возможности монолитных приложений ограничены используемыми технологиями.
- Развертывание. При внесении небольшого изменения потребуется повторное развертывание всего монолитного приложения.
